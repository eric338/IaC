# YAML 문법 함정

1. `~/lab/ex04` 디렉터리를 만들고, `ansible.cfg`에 `inventory = ~/lab/inventory.ini`를 등록하세요. 이후 이 장의 모든 실습은 이 디렉터리에서, `-i` 옵션 없이 진행합니다.
2. 부울 값 다섯 가지 표기(`yes`, `no`, `True`, `TRUE`, `false`)를 변수로 정의하고 `ansible.builtin.debug`로 출력하는 작업을 `yaml_bool.yml`에 작성해 `nodes` 그룹에 실행하고, 다섯 표기가 모두 `True`/`False` 두 값으로만 해석되는지 확인하세요.
3. `windows_drive: c:`처럼 콜론 뒤에 값이 오는 잘못된 표기를 `yaml_colon_bad.yml`에 작성해 `--syntax-check`로 오류가 나는지 확인하고, 작은따옴표로 감싸 고친 `yaml_colon_fixed.yml`을 작성해 문제없이 통과하는지 비교하세요.
4. `foo: "{{ variable }}/additional/string/literal"`처럼 사전 값 전체를 큰따옴표로 감싸 변수와 리터럴 문자열을 함께 쓰는 올바른 예제를 `yaml_var_quote.yml`에 작성하고, 값의 일부만 인용해 구문 오류가 나는 형태는 주석으로 함께 남겨 두 형태를 비교하세요.
5. `non_boolean: "yes"`, `version: "1.0"`처럼 부울/부동소수점으로 해석될 값을 따옴표로 강제로 문자열화하는 예제를 `yaml_string_force.yml`에 작성하고, 따옴표를 없앤 경우와 `ansible.builtin.debug` 출력이 어떻게 달라지는지 비교하세요.

1. 이미 작성되어 있는 `install_cowsay.yml`을 열어 `hosts`, `become`, `tasks` 키와 두 작업이 각각 어떤 모듈을 호출하는지 확인한 뒤 `nodes` 그룹을 대상으로 실행하세요.
2. 처음 실행한 결과의 PLAY RECAP에서 `changed` 값이 몇인지 확인하세요.
3. `install_cowsay.yml`을 다시 한번 그대로 실행해, 이번에는 모든 작업이 `changed` 없이 `ok`로만 보고되는 것을 확인하고 그 이유를 멱등성 개념으로 설명하세요.
4. `ansible.builtin.command`로 `date` 명령을 실행하는 작업을 `idempotence_break.yml`에 작성해 `nodes` 그룹에 두 번 연달아 실행하고, `install_cowsay.yml`의 cowsay 설치 작업과 달리 매번 `changed`로 보고되는 이유를 설명하세요.
5. `ansible nodes -b -m ansible.builtin.apt -a "name=cowsay state=absent"` ad-hoc 명령으로 cowsay를 제거한 뒤 `install_cowsay.yml`을 다시 실행해, cowsay 설치 작업만 `changed`로 나오고 마커 파일 배포 작업은 `ok`로 유지되는지 확인하세요.

1. `install_cowsay.yml`을 이미 한 번 실행해 둔 상태에서 `--check`로 실행해, 실제 변경 없이 `changed=0`으로 시뮬레이션되는지 확인하세요.
2. `ansible nodes -b -m ansible.builtin.apt -a "name=cowsay state=absent"`로 cowsay를 제거한 뒤 `--check` 모드로만 `install_cowsay.yml`을 실행해 보고, 실제로 cowsay가 설치되었는지 확인해 체크 모드가 "실제 실행 결과의 예측"이 아니라는 것을 검증하세요.

4. 이번에는 `--check` 없이 `--diff`만 사용해 실행해, 실제로 파일이 바뀌면서 diff도 함께 출력되는지 확인하세요.
