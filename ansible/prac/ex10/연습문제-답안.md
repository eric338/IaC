# 파일 암호화 기초

**1-1.** `~/lab/ex10` 디렉터리를 만들고 `ansible.cfg`에 `inventory = ~/lab/inventory.ini`를 등록하세요. 이후 이 장의 모든 실습은 이 디렉터리에서, `-i` 옵션 없이 진행합니다.

```bash
# ansible-ctrl에서 실행
mkdir -p ~/lab/ex10
cd ~/lab/ex10
```

— `~/lab/ex10/ansible.cfg`
```ini
[defaults]
inventory = ~/lab/inventory.ini
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible nodes --list-hosts
```

(예상 출력)
```
  hosts (2):
    ansible-node1
    ansible-node2
```

**1-2.** 단일 볼트 패스워드를 담은 패스워드 파일 `vault_pass`를 만들고(`chmod 600`), `db_secret.yml`(`db_password: S3cr3tP@ss` 한 줄)을 작성해 이 패스워드 파일로 암호화하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
echo 'testpass123' > vault_pass
chmod 600 vault_pass
```

— `~/lab/ex10/db_secret.yml` (암호화 전)
```yaml
db_password: S3cr3tP@ss
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault encrypt --vault-password-file vault_pass db_secret.yml
```

(예상 출력)
```
Encryption successful
```

— `~/lab/ex10/db_secret.yml` (암호화 후, 실제 파일 형태)
```
$ANSIBLE_VAULT;1.1;AES256
...(암호화된 내용, 실제 값은 실행 시 생성됨)...
```

패스워드 파일은 매번 다른 솔트(Salt)로 암호화되므로, 실제로 실행하면 위 예시와 다른 16진수 값이 나오는 것이 정상입니다.

**1-3.** `ansible-vault view`로 `db_secret.yml`의 내용을 확인하고, `ansible-vault edit`로 `db_user: admin` 줄을 추가한 뒤 다시 `view`로 두 값이 모두 있는지 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault view --vault-password-file vault_pass db_secret.yml
```

(예상 출력)
```
db_password: S3cr3tP@ss
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault edit --vault-password-file vault_pass db_secret.yml
```

편집기(`$EDITOR`, 기본값 vi)가 열리면 아래 줄을 추가하고 저장합니다.

```yaml
db_password: S3cr3tP@ss
db_user: admin
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault view --vault-password-file vault_pass db_secret.yml
```

(예상 출력)
```
db_password: S3cr3tP@ss
db_user: admin
```

**1-4.** 새 패스워드 파일 `new_vault_pass`를 만들고, `ansible-vault rekey`로 `db_secret.yml`의 패스워드를 `vault_pass`에서 `new_vault_pass`로 재지정하세요. 재지정 후 옛 패스워드 파일로 `view`를 시도해 실패하는지, 새 패스워드 파일로는 성공하는지 각각 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
echo 'newpass789' > new_vault_pass
chmod 600 new_vault_pass

ansible-vault rekey --vault-password-file vault_pass --new-vault-password-file new_vault_pass db_secret.yml
```

(예상 출력)
```
Rekey successful
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault view --vault-password-file vault_pass db_secret.yml
```

(예상 출력 — 옛 패스워드는 더 이상 통하지 않는다)
```

```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault view --vault-password-file new_vault_pass db_secret.yml
```

(예상 출력)
```
db_password: S3cr3tP@ss
db_user: admin
```

**1-5.** `ansible-vault decrypt`로 `db_secret.yml`을 평문으로 되돌리고 `cat`으로 내용을 확인하세요.

# Vault ID를 이용한 멀티 볼트 패스워드

작업 디렉터리는 `~/lab/ex10`입니다(문제 1의 1-1에서 만든 `ansible.cfg`를 그대로 씁니다).

**2-1.** 레이블별 패스워드 파일 `dev_pass`, `prod_pass`를 만드세요(`chmod 600`).

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
echo 'devpass111' > dev_pass
echo 'prodpass222' > prod_pass
chmod 600 dev_pass prod_pass
```

**2-2.** `dev_secret.yml`(`dev_api_key: DEV-KEY-111`)을 `dev` 레이블로, `prod_secret.yml`(`prod_api_key: PROD-KEY-999`)을 `prod` 레이블로 각각 `--vault-id label@source` 형식을 이용해 암호화하세요.

— `~/lab/ex10/dev_secret.yml` (암호화 전)
```yaml
dev_api_key: DEV-KEY-111
```

— `~/lab/ex10/prod_secret.yml` (암호화 전)
```yaml
prod_api_key: PROD-KEY-999
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault encrypt --vault-id dev@dev_pass dev_secret.yml
ansible-vault encrypt --vault-id prod@prod_pass prod_secret.yml
```

(예상 출력)
```
Encryption successful
Encryption successful
```

**2-3.** `head -1`로 두 파일의 헤더를 비교해, 형식 버전(`1.2`)과 레이블이 제대로 기록됐는지 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
head -1 dev_secret.yml prod_secret.yml
```

(예상 출력)
```
==> dev_secret.yml <==
$ANSIBLE_VAULT;1.2;AES256;dev

==> prod_secret.yml <==
$ANSIBLE_VAULT;1.2;AES256;prod
```

**2-4.** `--vault-id dev@prompt`로 `dev_secret.yml`을 `view`해, 프롬프트에 레이블(`Vault password (dev):`)이 함께 표시되는지 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault view --vault-id dev@prompt dev_secret.yml
```

(예상 출력 — 프롬프트에 devpass111을 입력)
```
Vault password (dev):
dev_api_key: DEV-KEY-111
```

**2-5.** `dev_secret.yml`을 엉뚱한 패스워드 파일(`prod_pass`)로 `view` 시도해, 패스워드가 맞지 않아 복호화가 실패하는 것을 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault view --vault-id dev@prod_pass dev_secret.yml
```

(예상 출력 — 레이블은 dev로 지정했지만 실제 패스워드 내용이 다르므로 복호화 실패)
```
[ERROR]: Failed to view 'dev_secret.yml': Decryption failed (no vault secrets were found that could decrypt).
```

`--vault-id`의 레이블(`dev`)은 어떤 파일에 어떤 패스워드를 쓸지 사람이 구분하기 위한 이름표일 뿐, Ansible이 파일 헤더의 레이블과 명령행 레이블을 비교해서 걸러내는 것은 아닙니다. 실제로 복호화가 되는지 여부는 오직 패스워드 값이 맞는지에 달려 있습니다.

# 변수 값 단위 암호화 (encrypt_string)

작업 디렉터리는 `~/lab/ex10`입니다.

**3-1.** `ansible-vault encrypt_string`으로 `vault_pass`를 이용해 변수명 `db_password`, 값 `S3cr3tP@ss`를 암호화하고, 출력된 `!vault` 블록을 `inline_vars.yml`이라는 플레이북의 `vars`에 붙여 넣으세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-vault encrypt_string --vault-password-file vault_pass --name db_password 'S3cr3tP@ss'
```

(예상 출력 — 암호문 부분은 플레이스홀더)
```
Encryption successful
db_password: !vault |
          $ANSIBLE_VAULT;1.1;AES256
          ...(암호화된 내용, 실제 값은 실행 시 생성됨)...
```

**3-2.** `inline_vars.yml`은 `nodes` 그룹을 대상으로, 복호화된 `db_password` 값을 `ansible.builtin.debug`로 출력하는 작업을 포함해야 합니다. `--vault-password-file vault_pass`로 실행해 값이 정상적으로 나오는지 확인하세요.

— `~/lab/ex10/inline_vars.yml`
```yaml
---
- name: 인라인 암호화 변수 사용 (단일 볼트 패스워드)
  hosts: nodes
  gather_facts: false
  vars:
    db_password: !vault |
              $ANSIBLE_VAULT;1.1;AES256
              ...(암호화된 내용, 실제 값은 실행 시 생성됨)...
  tasks:
    - name: 복호화된 변수 값 확인
      ansible.builtin.debug:
        msg: "db_password = {{ db_password }}"
```

> `!vault` 블록은 3-1에서 얻은 실제 출력값(들여쓰기를 맞춘 암호문 전체)으로 바꿔 넣어야 합니다. 위 예시의 플레이스홀더 그대로는 복호화되지 않습니다.

```bash
# ansible-ctrl에서 실행 (~/lab/ex10)
ansible-playbook --vault-password-file vault_pass inline_vars.yml
```

(예상 출력)


**3-3.** 이번에는 `--vault-id dev@dev_pass`를 이용해 변수명 `dev_api_key`, 값 `DEV-KEY-111`을 암호화하고, 같은 방식으로 `dev_inline.yml` 플레이북에 붙여 넣어 실행하세요.


# 암호화된 변수 파일을 사용하는 플레이북 실행

작업 디렉터리는 `~/lab/ex10`입니다.

**4-1.** `secret_vars.yml`(`db_password: S3cr3tP@ss`)을 작성해 `vault_pass`로 암호화하고, 이를 `vars_files`로 불러와 값을 출력하는 `site.yml`을 작성하세요.

— `~/lab/ex10/secret_vars.yml` (암호화 전)
```yaml

```


Ansible은 여러 `--vault-id`로 제공된 패스워드 후보를 모두 기억해 두었다가, 각 암호화된 파일마다 복호화가 성공하는 패스워드를 찾아서 적용합니다. 그래서 레이블이 서로 다른 두 파일을 하나의 플레이북에서 동시에 사용할 수 있습니다.

볼트 패스워드 파일은 이미 평문 그대로 디스크에 존재하므로, `.gitignore` 등록은 저장소에 커밋되는 것만 막을 뿐 파일 자체를 보호하지는 못합니다. 운영 환경에서는 이런 패스워드 파일을 별도의 비밀 관리 체계(예: Vault 서버, 환경 변수, CI/CD 시크릿)로 옮기는 것이 바람직합니다.
