# 파일 암호화 기초

1. `~/lab/ex10` 디렉터리를 만들고, `ansible.cfg`에 `inventory = ~/lab/inventory.ini`를 등록하세요. 이후 이 장의 모든 실습은 이 디렉터리에서, `-i` 옵션 없이 진행합니다.
2. 단일 볼트 패스워드를 담은 패스워드 파일 `vault_pass`를 만들고(`chmod 600`), `db_secret.yml`(`db_password: S3cr3tP@ss` 한 줄)을 작성해 이 패스워드 파일로 암호화하세요.
3. `ansible-vault view`로 `db_secret.yml`의 내용을 확인하고, `ansible-vault edit`로 `db_user: admin` 줄을 추가한 뒤 다시 `view`로 두 값이 모두 있는지 확인하세요.
4. 새 패스워드 파일 `new_vault_pass`를 만들고, `ansible-vault rekey`로 `db_secret.yml`의 패스워드를 `vault_pass`에서 `new_vault_pass`로 재지정하세요. 재지정 후 옛 패스워드 파일로 `view`를 시도해 실패하는지, 새 패스워드 파일로는 성공하는지 각각 확인하세요.
5. `ansible-vault decrypt`로 `db_secret.yml`을 평문으로 되돌리고 `cat`으로 내용을 확인하세요.

# Vault ID를 이용한 멀티 볼트 패스워드

1. 레이블별 패스워드 파일 `dev_pass`, `prod_pass`를 만드세요(`chmod 600`).
2. `dev_secret.yml`(`dev_api_key: DEV-KEY-111`)을 `dev` 레이블로, `prod_secret.yml`(`prod_api_key: PROD-KEY-999`)을 `prod` 레이블로 각각 `--vault-id label@source` 형식을 이용해 암호화하세요.
3. `head -1`로 두 파일의 헤더를 비교해, 형식 버전(`1.2`)과 레이블이 제대로 기록됐는지 확인하세요.
4. `--vault-id dev@prompt`로 `dev_secret.yml`을 `view`해, 프롬프트에 레이블(`Vault password (dev):`)이 함께 표시되는지 확인하세요.
5. `dev_secret.yml`을 엉뚱한 패스워드 파일(`prod_pass`)로 `view` 시도해, 패스워드가 맞지 않아 복호화가 실패하는 것을 확인하세요.

# 변수 값 단위 암호화 (encrypt_string)

1. `ansible-vault encrypt_string`으로 `vault_pass`를 이용해 변수명 `db_password`, 값 `S3cr3tP@ss`를 암호화하고, 출력된 `!vault` 블록을 `inline_vars.yml`이라는 플레이북의 `vars`에 붙여 넣으세요.
2. `inline_vars.yml`은 `nodes` 그룹을 대상으로, 복호화된 `db_password` 값을 `ansible.builtin.debug`로 출력하는 작업을 포함해야 합니다. `--vault-password-file vault_pass`로 실행해 값이 정상적으로 나오는지 확인하세요.
3. 이번에는 `--vault-id dev@dev_pass`를 이용해 변수명 `dev_api_key`, 값 `DEV-KEY-111`을 암호화하고, 같은 방식으로 `dev_inline.yml` 플레이북에 붙여 넣어 실행하세요.
4. `inline_vars.yml`을 열어 `!vault` 블록의 첫 줄(`$ANSIBLE_VAULT;1.1;AES256`)과 `dev_inline.yml`의 첫 줄(`$ANSIBLE_VAULT;1.2;AES256;dev`)을 비교해, 단일 볼트 패스워드와 Vault ID 방식의 헤더 차이를 확인하세요.

# 암호화된 변수 파일을 사용하는 플레이북 실행

1. `secret_vars.yml`(`db_password: S3cr3tP@ss`)을 작성해 `vault_pass`로 암호화하고, 이를 `vars_files`로 불러와 값을 출력하는 `site.yml`을 작성하세요.
2. 볼트 패스워드 없이 `ansible-playbook site.yml`을 실행해 어떤 오류가 나는지 확인한 뒤, `--ask-vault-pass`로 다시 실행해 정상 동작하는지 확인하세요.
3. 이번에는 `--vault-password-file vault_pass`로 실행해, 프롬프트 없이도 값이 복호화되는지 확인하세요.
4. `dev_vars.yml`(`dev_api_key: DEV-KEY-111`, `dev` 레이블), `prod_vars.yml`(`prod_api_key: PROD-KEY-999`, `prod` 레이블) 두 파일을 각각 암호화하고, 두 파일을 모두 `vars_files`로 불러와 두 값을 함께 출력하는 `multi.yml`을 작성하세요.
5. `multi.yml`을 `--vault-id dev@dev_pass --vault-id prod@prod_pass` 두 옵션을 함께 지정해 실행하고, 두 값이 모두 정상적으로 출력되는지 확인하세요.

# ansible.cfg에 볼트 설정 등록

1. `ansible.cfg`에 `vault_password_file = vault_pass`를 추가하고, `--vault-password-file` 옵션 없이 `ansible-playbook site.yml`을 실행해 여전히 정상 동작하는지 확인하세요.
2. `ansible.cfg`의 설정을 `vault_identity_list = dev@dev_pass, prod@prod_pass`로 바꾸고, `--vault-id` 옵션 없이 `multi.yml`을 실행해 두 값이 모두 복호화되는지 확인하세요.
3. `vault_identity_list`가 설정된 상태에서 `ansible-vault create --encrypt-vault-id prod newsecret.yml`로 새 파일을 만들고, `head -1`로 헤더의 레이블이 `prod`로 기록됐는지 확인하세요.
4. `.gitignore`에 패스워드 파일들(`vault_pass`, `new_vault_pass`, `dev_pass`, `prod_pass`)을 등록해, 실수로 평문 패스워드가 버전 관리 시스템에 올라가지 않도록 하세요. `git status`로 이 파일들이 추적되지 않는지 확인하세요.
