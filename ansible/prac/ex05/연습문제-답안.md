# 종합 실습 — 변수와 템플릿으로 웹서버 구성하기 (답안)

> 주의: 이 답안은 실제 Vagrant 랩 VM에서 실행해 검증한 것이 아니다. 아래의 실행 결과는 모두 Ansible/Jinja2의 동작 방식과 05장 본문(특히 5.5절의 팩트 키 이름)에 근거해 추정한 것이며, "(예상 출력)" 라벨을 붙여 표시한다. 실습 시에는 반드시 직접 실행해 실제 출력과 비교해야 한다.

인벤토리는 `~/lab/inventory.ini`를 그대로 사용한다(`control`/`nodes`/`broken` 그룹, `nodes` = `ansible-node1`, `ansible-node2`). 관리 노드의 사설망(enp0s9) 주소는 05장 본문 기준으로 `ansible-node1 = 192.168.56.51`, `ansible-node2 = 192.168.56.52`다.

## 문제 1 — Apache 설치

**1-1.** `~/lab/ex05-web` 디렉터리를 만들고 이동하세요. `ansible.cfg`에 `inventory = ~/lab/inventory.ini`를 등록해, 이후 이 실습의 모든 명령을 `-i` 옵션 없이 진행하세요.

```bash
# ansible-ctrl에서 실행
mkdir -p ~/lab/ex05-web
cd ~/lab/ex05-web
```

— `~/lab/ex05-web/ansible.cfg`
```ini
[defaults]
inventory = ~/lab/inventory.ini
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex05-web)
ansible nodes --list-hosts
```

```
(예상 출력)
  hosts (2):
    ansible-node1
    ansible-node2
```

**1-2.** `nodes` 그룹에 `apache2`를 설치하고, 서비스가 켜져 있는지(`started`) + 부팅 시 자동 실행(`enabled`)까지 보장하는 플레이북 `install_apache.yml`을 작성하세요.

— `~/lab/ex05-web/install_apache.yml`
```yaml
---
- name: Install and configure Apache
  hosts: nodes
  become: true

  tasks:
    - name: Ensure apache2 is installed
      ansible.builtin.apt:
        name: apache2
        state: present
        update_cache: true

    - name: Ensure apache2 is started and enabled
      ansible.builtin.service:
        name: apache2
        state: started
        enabled: true
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex05-web)
ansible-playbook install_apache.yml
```

## 문제 2 — 변수 + 팩트 + Jinja2 템플릿으로 index.html 배포

**2-1.** `install_apache.yml`의 `vars`에 `site_title`(예: "사내 웹서버")과 `site_owner`(담당 부서) 변수를 정의하세요.

**2-3.** `install_apache.yml`에 `ansible.builtin.template`으로 `/var/www/html/index.html`을 배포하는 태스크를 추가하세요.

2-1과 2-3을 반영한 `install_apache.yml` 전체 내용이다.

— `~/lab/ex05-web/install_apache.yml`
```yaml
---
- name: Install and configure Apache
  hosts: nodes
  become: true
  vars:
    site_title: "사내 웹서버"
    site_owner: "인프라운영팀"

  tasks:
    - name: Ensure apache2 is installed
      ansible.builtin.apt:
        name: apache2
        state: present
        update_cache: true

    - name: Ensure apache2 is started and enabled
      ansible.builtin.service:
        name: apache2
        state: started
        enabled: true

    - name: Deploy index.html from template
      ansible.builtin.template:
        src: templates/index.html.j2
        dest: /var/www/html/index.html
        mode: '0644'
```

**2-2.** 아래는 빈칸을 채운 `templates/index.html.j2`다.

- ① `site_title`
- ② `site_title`
- ③ `site_owner`
- ④ `ansible_facts['hostname']`
- ⑤ `ansible_facts['default_ipv4']['address']`

— `~/lab/ex05-web/templates/index.html.j2`
```jinja2
<!DOCTYPE html>
<html>
<head>
  <title>{{ site_title }}</title>
</head>
<body>
  <h1>{{ site_title }}</h1>
  <p>담당: {{ site_owner }}</p>
  <p>호스트: {{ ansible_facts['hostname'] }} ({{ ansible_facts['default_ipv4']['address'] }})</p>
</body>
</html>
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex05-web)
ansible-playbook install_apache.yml
curl -s http://192.168.56.51/
```

```
(예상 출력)
TASK [Deploy index.html from template] *******************************************
changed: [ansible-node1]
changed: [ansible-node2]

<!DOCTYPE html>
<html>
<head>
  <title>사내 웹서버</title>
</head>
<body>
  <h1>사내 웹서버</h1>
  <p>담당: 인프라운영팀</p>
  <p>호스트: ansible-node1 (10.0.2.15)</p>
</body>
</html>
```

> 참고: `default_ipv4`가 두 노드에서 같은 값으로 보이는 이유
> 05장 본문(5.5.2.1)에서 확인했듯, 이 랩 환경에서는 `ansible_facts['default_ipv4']['address']`가 기본 경로(NAT, `10.0.2.15`)를 가리키며 관리 노드 세 대 모두 이 값이 동일하다. 즉 위 예상 출력에서 `ansible-node1`과 `ansible-node2`의 페이지는 IP 표시 부분이 같은 `10.0.2.15`로 나올 것으로 예상된다 — 이것은 오류가 아니라 NAT 인터페이스를 공유하는 이 실습 환경의 정상적인 특성이다. 노드마다 다른 IP를 보여주고 싶다면 ⑤ 자리에 `ansible_facts['enp0s9']['ipv4']['address']`(사설망 주소, `192.168.56.51`/`192.168.56.52`로 서로 다름)를 대신 채워도 된다. 다만 `enp0s9`라는 인터페이스 이름은 환경마다 다를 수 있으므로, 실제 환경에서는 먼저 `ansible_facts['interfaces']`로 이름을 확인해야 한다(05장 5.5.2 참고).

## 문제 4 — `vars_prompt`로 배포 시점에 값 입력받기

**4-1.** `install_apache.yml`에 `vars_prompt`를 추가해 실행할 때마다 배포 환경(`deploy_env`, 기본값 `dev`)을 입력받도록 하고, 템플릿에 `deploy_env`를 출력하는 줄을 추가하세요.

## 문제 6 — 멱등성 확인

**6-1.** 아무것도 바꾸지 않고 플레이북을 다시 실행해, `changed=0`으로 수렴하는지 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex05-web)
ansible-playbook install_apache.yml
# 프롬프트에 이전과 같은 값(prod) 입력
```

```
(예상 출력)
TASK [Ensure apache2 is installed] ***********************************************
ok: [ansible-node1]
ok: [ansible-node2]

TASK [Ensure apache2 is started and enabled] *************************************
ok: [ansible-node1]
ok: [ansible-node2]

TASK [Deploy index.html from template] *******************************************
ok: [ansible-node1]

PLAY RECAP *************************************************************************
ansible-node1              : ok=4    changed=0    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
ansible-node2              : ok=4    changed=0    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
```

`ansible.builtin.apt`, `ansible.builtin.service`, `ansible.builtin.template` 세 모듈 모두 멱등성을 가지므로, 대상 상태(패키지 설치됨, 서비스 실행/활성화됨, 파일 내용 동일함)가 이미 충족되어 있으면 `changed` 없이 `ok`만 보고한다. 단, 매번 같은 값을 입력해야 렌더링된 파일 내용이 이전과 동일하게 유지되어 `changed=0`이 된다. `vars_prompt`에서 이전과 다른 값(예: `dev`)을 입력하면 템플릿 내용이 바뀌므로 `Deploy index.html from template` 작업이 다시 `changed`로 보고된다.

## 문제 7 — 환경 정리 (다음 apache2 실습을 위한 초기화)

**7-1.** 이번 실습에서 두 노드에 한 일 — `index.html` 배포, `apache2` 설치 — 를 되돌리는 플레이북 `cleanup_apache.yml`을 작성하세요. 패키지는 설정 파일까지 완전히 제거(`purge`)하고, 더 이상 필요 없는 의존 패키지도 함께 정리하세요.

— `~/lab/ex05-web/cleanup_apache.yml`
```yaml
---
- name: Clean up Apache installation
  hosts: nodes
  become: true

  tasks:
    - name: Stop and disable apache2
      ansible.builtin.service:
        name: apache2
        state: stopped
        enabled: false
      ignore_errors: true

    - name: Remove deployed index.html
      ansible.builtin.file:
        path: /var/www/html/index.html
        state: absent

    - name: Purge apache2 and its config files
      ansible.builtin.apt:
        name: apache2
        state: absent
        purge: true

    - name: Remove now-unneeded dependency packages
      ansible.builtin.apt:
        autoremove: true
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex05-web)
ansible-playbook cleanup_apache.yml
```

```
(예상 출력)
TASK [Stop and disable apache2] **************************************************
changed: [ansible-node1]
changed: [ansible-node2]

TASK [Remove deployed index.html] ************************************************
changed: [ansible-node1]
changed: [ansible-node2]

TASK [Purge apache2 and its config files] ****************************************
changed: [ansible-node1]
changed: [ansible-node2]

TASK [Remove now-unneeded dependency packages] ***********************************
changed: [ansible-node1]
changed: [ansible-node2]

PLAY RECAP *************************************************************************
ansible-node1              : ok=5    changed=4    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
ansible-node2              : ok=5    changed=4    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
```

**7-2.** 실행하고, `apache2`가 완전히 사라졌는지(패키지·서비스·페이지 응답 전부) 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex05-web)
ansible nodes -a "dpkg -l apache2"
ansible nodes -a "systemctl status apache2"
curl -s -o /dev/null -w 'ansible-node1 -> %{http_code}\n' http://192.168.56.51/
curl -s -o /dev/null -w 'ansible-node2 -> %{http_code}\n' http://192.168.56.52/
```

```
(예상 출력)
ansible-node1 | FAILED | rc=1 >>
dpkg-query: no packages found matching apache2
ansible-node2 | FAILED | rc=1 >>
dpkg-query: no packages found matching apache2

ansible-node1 | FAILED | rc=4 >>
Unit apache2.service could not be found.
ansible-node2 | FAILED | rc=4 >>
Unit apache2.service could not be found.

ansible-node1 -> 000
ansible-node2 -> 000
```

`dpkg -l`과 `systemctl status`가 모두 실패로 보고되는 것은 정상이다(패키지와 서비스가 존재하지 않으므로 조회 명령 자체가 0이 아닌 종료 코드를 반환한다). `curl`의 `%{http_code}`가 `000`으로 나오는 것은 해당 포트에 아무 것도 응답하지 않는다는 뜻이며, apache2가 완전히 제거되었음을 의미한다.
