**2-2.** `all:!broken` 패턴으로 `broken` 그룹을 제외한 호스트만 나오는지 확인하고, 이런 제외 패턴이 실무에서 왜 유용한지 생각해 보세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex03)
ansible 'all:!broken' --list-hosts
```

(예상 출력)
```
  hosts (3):
    ansible-ctrl
    ansible-node1
    ansible-node2
```

`broken` 그룹의 `ansible-node9`(`ansible_host=192.168.56.99`)는 실제로 존재하지 않는 IP를 가리키므로, 전체 대상으로 작업을 실행할 때 `all:!broken`처럼 제외해 두면 연결이 되지 않는 노드 때문에 플레이가 중단되거나 전체 실행 시간이 늘어지는 것을 막을 수 있습니다. 아직 준비되지 않았거나 점검이 필요한 노드를 격리해 두는 용도로도 씁니다.

**2-3.** `webservers`(foo, bar), `dbservers`(one, two), `east`(foo, one), `west`(bar, two)가 겹치도록 구성한 `pattern_inventory.ini`를 작성하고, 합집합(`:`), 교집합(`:&`), 제외(`:!`) 패턴을 각각 `--list-hosts`로 실행해 결과를 비교하세요.

— `~/lab/ex03/pattern_inventory.ini`
```ini
[webservers]
foo.example.com
bar.example.com

[dbservers]
one.example.com
two.example.com

[east]
foo.example.com
one.example.com

[west]
bar.example.com
two.example.com
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex03)
ansible 'webservers:dbservers' -i pattern_inventory.ini --list-hosts
ansible 'webservers:!west' -i pattern_inventory.ini --list-hosts
ansible 'webservers:&east' -i pattern_inventory.ini --list-hosts
```

(예상 출력)
```
  hosts (4):
    foo.example.com
    bar.example.com
    one.example.com
    two.example.com

  hosts (1):
    foo.example.com

  hosts (1):
    foo.example.com
```

`webservers:dbservers`는 두 그룹의 합집합 4대, `webservers:!west`는 웹 서버 중 `west`가 아닌 것, `webservers:&east`는 웹 서버이면서 동시에 `east`인 것입니다. 뒤 두 개는 결과가 우연히 같은 `foo.example.com` 하나지만 계산 방식(제외 vs 교집합)은 다릅니다.

**2-4.** 3번 인벤토리에 대해 `webservers:dbservers:&east:!west` 같은 혼합 패턴을 실행하고, 어떤 순서로 계산되어 그 결과가 나왔는지 설명하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex03)
ansible 'webservers:dbservers:&east:!west' -i pattern_inventory.ini --list-hosts
```

(예상 출력)
```
  hosts (2):
    foo.example.com
    one.example.com
```

`webservers`와 `dbservers`를 합쳐 4대(foo, bar, one, two)를 만든 다음, 그중 `east`에 속하는 것만 남기고(foo, one), 마지막으로 `west`에 속하는 것을 뺀 결과입니다. 이번 대상 범위에는 `west`에 속하는 호스트가 이미 없으므로 마지막 단계에서는 아무것도 빠지지 않습니다.

**2-5.** `pattern_inventory.ini`에 와일드카드 패턴(`*.example.com`)을 실행해 보고, 이어서 호스트 이름이 `web`, `db`로 시작하는 것만 걸러내는 정규 표현식 인벤토리(`regex_inventory.ini`)와 패턴(`~(web|db).*`)을 작성해 실행하세요. 패턴을 따옴표 없이 실행하면 어떤 문제가 생기는지도 확인하세요.

```bash
# ansible-ctrl에서 실행 (~/lab/ex03)
ansible '*.example.com' -i pattern_inventory.ini --list-hosts
```

(예상 출력) `pattern_inventory.ini`의 호스트는 모두 `.example.com`으로 끝나므로 전부 걸립니다.
```
  hosts (4):
    foo.example.com
    bar.example.com
    one.example.com
    two.example.com
```

— `~/lab/ex03/regex_inventory.ini`
```ini
[webservers]
web01.example.com
web02.example.com

[dbservers]
db01.example.com

[others]
mail.example.com
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex03)
ansible '~(web|db).*\.example\.com' -i regex_inventory.ini --list-hosts
```

(예상 출력)
```
  hosts (3):
    web01.example.com
    web02.example.com
    db01.example.com
```

이름이 `web` 또는 `db`로 시작하는 호스트만 걸리고 `mail.example.com`은 제외됩니다.

```bash
# ansible-ctrl에서 실행 (~/lab/ex03) — 따옴표 없이 실행
ansible ~(web|db).*\.example\.com -i regex_inventory.ini --list-hosts
```

(예상 출력) 셸이 `~`와 `(`, `|`, `)`를 먼저 해석해 버려 Ansible에 온전한 패턴 문자열이 전달되지 않습니다. 셸 환경에 따라 `command not found`, `event not found` 등 셸 자체의 오류가 나거나, Ansible이 전혀 다른 문자열을 패턴으로 받아 다음과 같은 경고를 내고 아무 것도 실행하지 않습니다.
```
[WARNING]: Could not match supplied host pattern, ignoring: ...
[WARNING]: No hosts matched, nothing to do
```

`*`, `~`, `!`, `&`처럼 셸이 특별하게 해석하는 문자가 패턴에 들어가면 반드시 작은따옴표로 감싸야 합니다.


```bash

```

(예상 출력)
```
CONFIG_FILE() = /home/vagrant/lab/ex03/cfgtest/env-ansible.cfg
DEFAULT_FORKS(/home/vagrant/lab/ex03/cfgtest/env-ansible.cfg) = 42

GALAXY_SERVERS:
```

`ansible.cfg`에 정의했던 `DEFAULT_REMOTE_USER(=vagrant)`가 목록에서 사라졌습니다. 두 파일이 합쳐졌다면 `env-ansible.cfg`의 `forks = 42`와 `ansible.cfg`의 `remote_user = vagrant`가 함께 나와야 하는데 그렇지 않습니다. `ANSIBLE_CONFIG`(1번)에서 파일을 찾은 순간 `./ansible.cfg`(2번)는 통째로 무시된 것입니다.

**3-4.** `cfgtest/ansible.cfg`가 적용되는 디렉터리에서, 옵션 없이 `whoami`를 실행했을 때, 존재하지 않는 사용자를 `-u`로 지정했을 때, 그리고 `-e ansible_user=vagrant`를 추가로 지정했을 때 세 가지 경우의 결과를 각각 실행해 비교하고, 구성 파일 · 명령줄 옵션 · `-e` 변수의 우선순위를 정리하세요.



(예상 출력) 명령줄 `-u` 옵션이 구성 파일의 값을 덮어쓰므로, 존재하지 않는 사용자로 접속을 시도하다 실패합니다.
