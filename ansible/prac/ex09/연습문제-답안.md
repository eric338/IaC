**3-2.** `dynamic_include.yml`을 작성해 역할 실행 전후에 `debug` 메시지를 두고, `tasks:` 안에서 `ansible.builtin.include_role`로 `motd_banner`를 동적으로 포함해 실행하세요. `included: motd_banner for ...` 줄이 나타나는지 확인하세요.

— `~/lab/ex09/dynamic_include.yml`
```yaml
---
- name: 역할 동적 포함
  hosts: nodes
  tasks:
    - name: 역할 실행 전 메시지
      ansible.builtin.debug:
        msg: "motd_banner 역할 실행 전"

    - name: motd_banner 동적으로 포함
      ansible.builtin.include_role:
        name: motd_banner

    - name: 역할 실행 후 메시지
      ansible.builtin.debug:
        msg: "motd_banner 역할 실행 후"
```

```bash

ansible-playbook dynamic_include.yml
```

(예상 출력)
```

ok: [ansible-node1] => { "msg": "motd_banner 역할 실행 전" }
ok: [ansible-node2] => { "msg": "motd_banner 역할 실행 전" }

TASK [motd_banner 동적으로 포함] ****************************************************
included: motd_banner for ansible-node1, ansible-node2

TASK [motd_banner : motd 배너 배포] *************************************************
ok: [ansible-node1]
ok: [ansible-node2]

TASK [역할 실행 후 메시지] *********************************************************
ok: [ansible-node1] => { "msg": "motd_banner 역할 실행 후" }
ok: [ansible-node2] => { "msg": "motd_banner 역할 실행 후" }
```

`included: motd_banner for ansible-node1, ansible-node2` 줄이 역할의 작업보다 먼저 출력되어, `include_role`이 실행 시점에 역할을 펼친다는 것을 보여줍니다.

**3-3.** `static_import.yml`을 작성해 같은 구성을 `ansible.builtin.import_role`로 만드세요. `ansible-playbook static_import.yml --list-tasks`와 `ansible-playbook dynamic_include.yml --list-tasks`의 결과를 비교해 두 방식의 차이(파싱 시점에 펼쳐지는지, 실행 시점에 펼쳐지는지)를 설명하세요.

— `~/lab/ex09/static_import.yml`
```yaml
---
- name: 역할 정적 포함
  hosts: nodes
  tasks:
    - name: 역할 실행 전 메시지
      ansible.builtin.debug:
        msg: "motd_banner 역할 실행 전"

    - name: motd_banner 정적으로 가져오기
      ansible.builtin.import_role:
        name: motd_banner

    - name: 역할 실행 후 메시지
      ansible.builtin.debug:
        msg: "motd_banner 역할 실행 후"
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex09)
ansible-playbook static_import.yml --list-tasks
ansible-playbook dynamic_include.yml --list-tasks
```

(예상 출력)
```
playbook: static_import.yml

  play #1 (nodes): 역할 정적 포함	TAGS: []
    tasks:
      역할 실행 전 메시지	TAGS: []
      motd_banner : motd 배너 배포	TAGS: []
      역할 실행 후 메시지	TAGS: []

playbook: dynamic_include.yml

  play #1 (nodes): 역할 동적 포함	TAGS: []
    tasks:
      역할 실행 전 메시지	TAGS: []
      motd_banner 동적으로 포함	TAGS: []
      역할 실행 후 메시지	TAGS: []
```

`import_role`은 플레이북을 파싱하는 시점에 역할의 작업 목록이 이미 펼쳐지므로 `--list-tasks`에 `motd_banner : motd 배너 배포`라는 실제 작업 이름이 그대로 나타납니다. 반면 `include_role`은 실행 시점이 되어야 어떤 작업이 포함될지 결정되므로, `--list-tasks` 단계에서는 `include_role` 작업 자체(`motd_banner 동적으로 포함`)만 보이고 그 안의 개별 작업은 보이지 않습니다.

**3-4.** `dynamic_include.yml`의 `include_role`에 `when: ansible_facts['os_family'] == 'Debian'` 조건을 추가해, 조건에 따라 역할 포함 여부가 달라지는 것을 실행으로 확인하세요.

— `~/lab/ex09/dynamic_include.yml` (수정)
```yaml
---
- name: 역할 동적 포함
  hosts: nodes
  tasks:
    - name: 역할 실행 전 메시지
      ansible.builtin.debug:
        msg: "motd_banner 역할 실행 전"

    - name: motd_banner 동적으로 포함
      ansible.builtin.include_role:
        name: motd_banner
      when: ansible_facts['os_family'] == 'Debian'

    - name: 역할 실행 후 메시지
      ansible.builtin.debug:
        msg: "motd_banner 역할 실행 후"
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex09)
ansible-playbook dynamic_include.yml
```

(예상 출력)
```
TASK [motd_banner 동적으로 포함] ****************************************************
included: motd_banner for ansible-node1, ansible-node2

TASK [motd_banner : motd 배너 배포] *************************************************
ok: [ansible-node1]
ok: [ansible-node2]
```

실습 환경의 관리 노드는 Ubuntu(`os_family: Debian` 계열)이므로 조건이 참이 되어 역할이 그대로 포함됩니다. `when`을 `ansible_facts['os_family'] == 'RedHat'`처럼 거짓이 되는 조건으로 바꾸면 `motd_banner 동적으로 포함` 작업 자체가 `skipping`으로 표시되고, `include_role` 안의 작업은 아예 나타나지 않습니다. `import_role`은 파싱 시점에 이미 펼쳐지므로 `when`을 걸어도 역할 내부의 각 작업마다 조건이 개별 적용된다는 차이가 있습니다.

**4-3.** `group_vars/nodes.yml` 파일을 만들어 `banner_message`를 정의한 뒤, 역할별 `vars:`를 주지 않은 `site.yml`을 다시 실행하세요. `group_vars`의 값과 역할 `vars/main.yml`의 값 중 어느 쪽이 배포되는지 확인하고 이유를 설명하세요.

— `~/lab/ex09/group_vars/nodes.yml`
```yaml
---
banner_message: "Managed by Ansible (group_vars/nodes)"
```

— `~/lab/ex09/site.yml` (역할 파라미터 제거)
```yaml
---
- name: motd 배너 배포 (roles 키워드, 역할 파라미터 없음)
  hosts: nodes
  roles:
    - motd_banner
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex09)

```

(예상 출력)
```

====================================
 Managed by Ansible (vars/main.yml - 우선순위 높음)
 host: ansible-node1
====================================
```

`group_vars/nodes.yml`의 값이 아니라 역할의 `vars/main.yml`(2-5에서 정의) 값이 그대로 배포됩니다. Ansible 변수 우선순위표에서 `group_vars`(인벤토리/플레이북 그룹 변수)는 상위권에 있지만, 역할의 `vars/main.yml`은 그보다 더 높은 우선순위 구간(역할 변수)에 속하기 때문입니다. 즉 "역할 안에서 명시적으로 정의한 변수"는 인벤토리 쪽 `group_vars`/`host_vars`보다 강합니다. 이 값을 이기려면 4-1처럼 역할에 직접 `vars:`를 전달하거나(역할 파라미터), 4-4의 `--extra-vars`를 써야 합니다.

**4-4.** `ansible-playbook site.yml --extra-vars "banner_message=..."` 형태로 실행해, 역할에 직접 전달한 변수보다도 `--extra-vars`가 우선하는지 확인하세요.

`--extra-vars`는 Ansible 변수 우선순위에서 항상 최상위이므로, 역할의 `vars/main.yml`이나 역할에 전달한 `vars:`, `group_vars`를 모두 덮어씁니다.

**5-4.** `deps_practice.yml`을 변형해 `roles:` 대신 `tasks:` 안에서 `include_role`로 `welcome_page`를 가져오는 `deps_include.yml`을 작성하고, `meta/main.yml`의 의존성이 `include_role`을 통해서도 그대로 실행되는지 확인하세요.

— `~/lab/ex09/deps_include.yml`
```yaml
---
- name: include_role 로 의존성 확인
  hosts: ansible-node1
  tasks:
    - name: welcome_page 역할을 동적으로 포함
      ansible.builtin.include_role:
        name: welcome_page
```

```bash
# ansible-ctrl에서 실행 (~/lab/ex09)
ansible-playbook deps_include.yml
```

(예상 출력)
```
TASK [welcome_page 역할을 동적으로 포함] *********************************************
included: welcome_page for ansible-node1

TASK [motd_banner : motd 배너 배포] *************************************************
changed: [ansible-node1]

TASK [motd_banner : motd 배너 배포] *************************************************
changed: [ansible-node1]

TASK [welcome_page : welcome_page 역할 작업] ****************************************
ok: [ansible-node1]
```

09장 9.1.6의 참고에서 설명한 것처럼, 오래된 자료에는 `include_role`/`import_role`로 역할을 가져오면 `meta/main.yml`의 의존성이 실행되지 않는다고 나오지만 현재 버전(ansible-core 2.21.3)에서는 두 방식 모두 의존 역할을 정상적으로 실행합니다. 다만 `roles:` 키워드와 달리 `include_role`/`import_role`은 `tasks:` 목록 안에서 실행되므로, 이 의존성이 `pre_tasks`/`tasks`/`post_tasks` 중 어느 시점에 끼어드는지는 그 역할을 포함한 위치에 따라 달라진다는 점에 유의해야 합니다.
