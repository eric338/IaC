# Packer로 Vagrant 박스 만들기

## 1. 기본 개념

### Vagrant box란
- `vagrant up`으로 띄우는 VM의 원본 이미지 파일(`.box`)
- 구성: 가상 디스크 이미지 + `metadata.json`(공급자·버전 정보)을 압축한 tar 파일

### Packer란
- HashiCorp의 머신 이미지 빌드 도구
- 흐름: ISO → OS 설치 → 패키지 설치·설정 → 정리, 전 과정을 스크립트로 자동 실행
- 결과물: VirtualBox `.box`, AWS AMI, Docker 이미지 등 원하는 형식으로 포장

### `vagrant package` vs Packer
- `vagrant package`: 떠 있는 VM을 그대로 굳혀서 박스화. 빠르지만 생성 과정은 기록 안 됨
- Packer: 매번 빈 디스크부터 재구성. 설치 전 과정이 설정 파일에 남음 → 재현·리뷰·CI 가능

### 전체 흐름
1. ISO 준비 — 설치 ISO, 체크섬 확보
2. 무인 설치 파일 준비 — Ubuntu(최신): cloud-init 기반 autoinstall / 구버전·Debian: preseed / RHEL 계열: kickstart
3. Packer 템플릿 작성 — `source`(설치 방식) + `build`(프로비저너 + 포스트프로세서)
4. 빌드 실행 — Packer가 VM을 직접 띄워 설치 진행
5. Vagrant 등록·검증
6. (선택) Vagrant Cloud 등 배포

### 용어
| 용어 | 의미 |
|---|---|
| Builder / `source` | 플랫폼·스펙 정의 |
| Provisioner | VM 기동 후 실행할 스크립트·설정 |
| Post-processor | 빌드 결과 후가공(`.box` 포장, 클라우드 업로드 등) |
| `required_plugins` | 필요 플러그인·버전 선언. `packer init`이 참조 |
| HCL2 | 현재 표준 템플릿 문법(과거: JSON) |

## 2. 공식 문서 코드 조각

- 조각별 출처 명시. 전체 조합·실행 검증은 안 된 상태
- 사용 전 원본 페이지 확인 및 본인 환경 검증 필수

### 2-1. 플러그인 선언 (`required_plugins`)

VirtualBox 플러그인:
```hcl
packer {
    required_plugins {
        virtualbox = {
          version = "~> 1"
          source  = "github.com/hashicorp/virtualbox"
        }
    }
}
```
출처: https://developer.hashicorp.com/packer/integrations/hashicorp/virtualbox

Vagrant 플러그인:
```hcl
packer {
  required_plugins {
    vagrant = {
        version = ">= 1.1.1"
        source = "github.com/hashicorp/vagrant"
    }
  }
}
```
출처: https://developer.hashicorp.com/packer/tutorials/aws-get-started/aws-get-started-post-processors-vagrant

### 2-2. VirtualBox ISO 빌더 — 기본 필드

```hcl
source "virtualbox-iso" "basic-example" {
  guest_os_type    = "Ubuntu_64"
  iso_url          = "..."   # 실습 대상 버전(예: 24.04)의 실제 ISO 주소
  iso_checksum     = "..."   # 2-3 참고 — file: 방식 시 해시 직접 기재 불필요
  ssh_username     = "..."
  ssh_password     = "..."
  shutdown_command = "echo '<password>' | sudo -S shutdown -P now"
}

build {
  sources = ["source.virtualbox-iso.basic-example"]
}
```
출처: https://developer.hashicorp.com/packer/integrations/hashicorp/virtualbox/latest/components/builder/iso

- 공식 예제의 `iso_url` 값은 Ubuntu 12.04 기준 → 값 제외, 필드명만 발췌
- 필드명(`guest_os_type`, `iso_url`, `iso_checksum`, `ssh_username`/`ssh_password`, `shutdown_command`)은 버전 무관, 현행 문법

### 2-3. `file:` 체크섬

- 해시값 수기 기재 불필요 — 배포처의 체크섬 파일 URL을 그대로 전달, Packer가 자동 대조

```hcl
iso_checksum = "file:https://releases.ubuntu.com/24.04/SHA256SUMS"
```

- `file:` 접두사 지원은 Packer ISO 설정 공통 기능
- 상세 동작: 2-2 출처 페이지의 "ISO Configuration" 항목 참조

### 2-4. `cd_files` / `cd_content` — autoinstall 데이터 전달

- Ubuntu 20.04 이후 cloud-init 기반 autoinstall의 데이터 전달 방식 중 하나
- HTTP 서빙 방식(preseed류) 대신 `user-data`/`meta-data`를 CD-ROM 형태로 부착

```hcl
cd_files = ["vendor-data"]
cd_content = {
  "meta-data" = jsonencode(local.instance_data)
  "user-data" = templatefile("user-data", { packages = ["nginx"] })
}
cd_label = "cidata"
```
출처: https://developer.hashicorp.com/packer/integrations/hashicorp/virtualbox/latest/components/builder/ovf

- 관련 근거: Hyper-V ISO 빌더 문서 — "Ubuntu 20.04 autoinstall 등 무인 설치용 CD 생성 시 사용" 명시
  https://developer.hashicorp.com/packer/plugins/builders/hyperv/iso

### 2-5. `boot_command` — 커널에 autoinstall 파라미터 전달

- 주의: 공식 문서의 `boot_command` 예제는 Ubuntu 12.04·CentOS 6.4 기준에 머물러 있음
- 22.04/24.04용 공식 예제 부재 → 아래는 공식 인용이 아닌, 검색으로 확인한 실사용 패턴

```text
linux /casper/vmlinuz --- autoinstall ds=nocloud-net;s=http://{{ .HTTPIP }}:{{ .HTTPPort }}/
```

- `/casper/vmlinuz`: Ubuntu live-server ISO(22.04, 24.04 포함)의 실제 커널 경로
- `ds=nocloud-net;s=...`: cloud-init에 user-data/meta-data 수신 주소를 알려주는 datasource 지정
- `<esc>`/`<wait>`/`<enter>` 등 키 입력 타이밍: GRUB 화면 구성에 따라 상이 → 콘솔 확인 후 조정 필요

참고:
- HashiCorp Packer 이슈 트래커, Ubuntu 22.04 autoinstall 논의 — https://github.com/hashicorp/packer/issues/12640
- Canonical 공식 Autoinstall 문서, Ubuntu Server 20.04 이상 지원 명시 — https://ubuntu.com/server/docs/install/autoinstall (접속 시 canonical-subiquity.readthedocs-hosted.com으로 리다이렉트)

### 2-6. Vagrant / Vagrant Cloud 포스트프로세서

```hcl
build {
  sources = ["source.null.autogenerated_1"]

  post-processor "shell-local" {
    inline = ["echo Doing stuff..."]
  }
  post-processors {
    post-processor "vagrant" {
      include              = ["image.iso"]
      output               = "proxycore_{{.Provider}}.box"
      vagrantfile_template = "vagrantfile.tpl"
    }
    post-processor "vagrant-cloud" {
      access_token = "${var.cloud_token}"
      box_tag      = "hashicorp/precise64"
      version      = "${local.version}"
      architecture = "${local.architecture}"
    }
  }
}
```
출처: https://developer.hashicorp.com/packer/integrations/hashicorp/vagrant/latest/components/post-processor/vagrant-cloud

- `vagrant` 포스트프로세서: 빌드 결과를 `.box`로 포장
- `vagrant-cloud` 포스트프로세서: 포장된 `.box`를 Vagrant Cloud로 업로드(계정·토큰 필요, 선택)

## 3. 자주 쓰는 명령어

```bash
# 도구 설치 확인
packer version
vagrant version
VBoxManage --version

# Packer 빌드 사이클
packer init .          # required_plugins 플러그인 다운로드
packer validate .       # 템플릿 문법/설정 검증 (빌드 전 필수)
packer build .          # 실제 빌드 실행

# 변수를 즉석에서 전달
packer build -var 'iso_url=https://example.com/ubuntu.iso' .

# 여러 source 중 하나만 빌드
packer build -only=virtualbox-iso.ubuntu-noble .

# 만든 박스를 Vagrant에 등록·확인
vagrant box add <박스이름> <파일경로 또는 URL> --force
vagrant box list
vagrant box remove <박스이름>

vagrant init <박스이름>
vagrant up
vagrant ssh
vagrant destroy -f

# 무인 설치 파일 작성 시
openssl passwd -6 '원하는비밀번호'   # cloud-init/유닉스 계정 비밀번호 해시 생성
sha256sum ubuntu-24.04-live-server-amd64.iso   # ISO 체크섬 직접 확인
```
